# FPGA问题单格式更新说明

## 更新日期
2024年11月11日

## 更新内容

### 一、输出列结构变更

**原格式（12列）**：
1. 问题名称
2. 问题来源
3. 问题复现
4. 问题解释
5. 测试活动
6. 问题类型
7. 问题等级
8. 问题数目
9. 问题名称（重复）
10. 问题来源（重复）
11. 问题描述（四段式）
12. 测评单位意见

**新格式（8列）**：
1. 测试活动
2. 问题类型
3. 问题等级
4. 问题数目
5. 问题名称
6. 问题来源
7. 问题描述（四段式）
8. 测评单位意见

### 二、字段填充规则

#### 1. 测试活动（第1列）
- **固定值**：`代码审查`

#### 2. 问题类型（第2列）
- **固定值**：`程序问题`

#### 3. 问题等级（第3列）
- **固定值**：`一般问题`

#### 4. 问题数目（第4列）
- **固定值**：`1`

#### 5. 问题名称（第5列）
- **数据源**：数据库 `fpga_rules` 表的 `issue_title` 字段
- **回退方案**：如果 `issue_title` 为空，使用 `{rule_code} - {rule_content前30字符}`

#### 6. 问题来源（第6列）
- **格式**：`{文件路径}文件{行号}行`
- **示例**：`top.v文件123行`

#### 7. 问题描述（四段式）（第7列）

**格式结构**：
```
需求描述：根据《可编程逻辑器件软件编码规范（Verilog篇）》{规则编号}要求：{规则内容}。
问题描述：{问题名称}。
问题定位：{问题来源}，具体内容如下："{源代码或问题描述}"，如上述内容所示，{问题名称}。
影响分析：{影响分析内容}
```

**字段说明**：
- **规范文档名称**：根据 `language` 字段自动判断
  - `VERILOG` → `《可编程逻辑器件软件编码规范（Verilog篇）》`
  - `VHDL` → `《可编程逻辑器件软件编码规范（VHDL篇）》`
- **规则编号**：`rule_code` 字段（如 `A-1-5`）
- **规则内容**：`rule_content` 字段
- **问题名称**：`issue_title` 字段
- **问题来源**：`{文件}文件{行号}行`
- **具体内容**：优先使用 `source_code`，否则使用 `issue_description`
- **影响分析**：数据库 `fpga_rules` 表的 `impact_analysis` 字段

#### 8. 测评单位意见（第8列）

**格式**：
```
1.请开发人员确认是否是问题
2.若是问题，{修改意见内容}
```

**字段说明**：
- **修改意见内容**：数据库 `fpga_rules` 表的 `fix_suggestion` 字段
- **特殊处理**：自动剔除 `fix_suggestion` 字段中的 `"修改意见："` 或 `"修改意见:"` 前缀

### 三、数据库字段依赖

本次更新依赖 `fpga_rules` 表的以下字段：

| 字段名 | 类型 | 说明 | 用途 |
|--------|------|------|------|
| `rule_code` | String(50) | 规则编号 | 需求描述、问题定位 |
| `rule_content` | Text | 规则内容 | 需求描述 |
| `language` | String(20) | 语言类型 | 确定规范文档名称 |
| `issue_title` | Text | 问题名称 | 问题名称列、问题描述 |
| `impact_analysis` | Text | 影响分析 | 四段式的影响分析部分 |
| `fix_suggestion` | Text | 修改意见 | 测评单位意见 |

### 六、注意事项

1. **数据完整性**：确保 `fpga_rules` 表中的 `issue_title`、`impact_analysis`、`fix_suggestion` 字段已填充
2. **语言识别**：`language` 字段必须是 `VERILOG` 或 `VHDL`（大小写不敏感）
3. **前缀处理**：`fix_suggestion` 字段如果包含 `"修改意见："` 前缀会自动剔除
4. **回退机制**：如果数据库字段为空，会使用默认值或组合值
5. **Excel格式**：前6列宽度为20，后2列宽度为60，行高统一为40
