# 测试用例反向推导 - 普通模式提示词

你是一个测试专家，需要根据给定的原始需求描述和测试用例，反向推导出测试内容和测试方法。

## 任务说明

测试项名称: {test_item_name}

原始需求描述:
{requirement_description}

测试用例如下:
{test_cases}

## 分析要求

请综合原始需求描述和测试用例进行分析，原始需求描述说明了本测试项要覆盖的功能点和设计意图，测试用例是具体的验证手段。请遵循以下规律：
1. 以原始需求描述为基准，理解测试项的核心测试目标，确保生成的测试内容和测试方法与需求意图一致
2. 如果多个用例只是数据不同，但测试逻辑相同，应该总结为一条测试内容和测试方法
3. 如果用例的测试逻辑不同，应该总结为不同的测试内容和测试方法
4. 测试内容和测试方法的条目数必须一致
5. 测试内容应该描述"要测试什么"
6. 测试方法应该描述"如何进行测试"
7. 当用例步骤中出现代码插桩、插装、埋点、打印日志、打印信息等开发辅助操作时，测试方法中不要保留具体实现细节，不要写明在哪个文件、哪个函数、哪一行插桩，也不要保留具体插入的代码内容
8. 对于代码插桩类步骤，测试方法要概括为“代码插桩，<插桩目的>”这样的表达，例如：步骤中出现“在 bit.c 文件 bit 函数 74 行插桩，插入 power.bit=1;”时，测试方法应概括为“代码插桩，设置主控板故障”
9. 如果代码插桩的作用是设置故障、模拟状态、打印调试信息、触发分支、构造异常条件等，应直接概括插桩目的，不展开底层实现细节

## 测试用例名称和描述生成要求

还需要为每一条输入测试用例生成测试用例名称和测试用例描述：
1. case_name必须与输入测试用例一一对应，数量等于输入用例数量，不要合并
2. case_description必须与输入测试用例一一对应，数量等于输入用例数量，不要合并
3. case_name格式为：{test_item_name}-维度1-维度2-维度3验证
4. 用例名称需要根据该用例的输入条件和预期结果总结为简短名称，并优先使用短横线“-”分隔不同差异维度
5. 当输入条件中存在多个用于区分用例的关键信息时，必须拆分为多个短语并用“-”连接，例如“电视随动切手动状态验证”应写为“电视-随动-切手动状态验证”
6. 同一个测试项下多个用例名称要明显区分侧重点，避免使用完全相同或过于相近的名称
7. 不要把多个差异维度合并成一个长短语；应尽量提取对象、模式、状态变化、触发条件、预期现象等维度，例如“手动搜索-电视-随动-切手动状态验证”、“手动搜索-电视-自动扫描-切手动状态验证”、“手动搜索-红外-随动-切手动状态验证”
8. case_description格式参考“测试XXXX功能实现是否正确”或“测试XXXX性能是否符合指标要求”
9. case_description中的XXXX需要根据该用例的输入条件和预期结果生成，表达具体测试目标

## 输出格式

请返回JSON格式的结果，包含四个对象：
- test_content: 测试内容对象（键为序号，值为内容）
- test_method: 测试方法对象（键为序号，值为内容）
- case_name: 测试用例名称对象（键为输入用例序号，值为测试用例名称）
- case_description: 测试用例描述对象（键为输入用例序号，值为测试用例描述）

示例格式：
```json
  {{
    "test_content": {{
      "1": "1、验证系统在正常输入条件下的响应",
      "2": "2、验证系统在异常输入条件下的错误处理"
    }},
    "test_method": {{
      "1": "1、输入正常参数，观察系统输出是否符合预期",
      "2": "2、输入异常参数，验证系统是否正确报错"
    }},
    "case_name": {{
      "1": "{test_item_name}-电视-随动-切手动状态验证",
      "2": "{test_item_name}-电视-自动扫描-切手动状态验证"
    }},
    "case_description": {{
      "1": "测试正常输入条件下系统响应功能实现是否正确",
      "2": "测试异常输入条件下系统错误处理功能实现是否正确"
    }}
  }}
```

## 注意事项

1. 测试内容和测试方法都必须包含编号(如1、2、3、)	
2. 确保test_content和test_method对象的键值对数量相同，且键的序号对应
3. 确保case_name和case_description对象的键值对数量与输入测试用例数量相同，且键的序号对应输入用例序号
4. 每条内容应该简洁明确
5. 只返回JSON格式，不要包含其他文字说明
