# 测试用例反向推导 - 普通模式提示词

你是一个测试专家，需要根据给定的测试用例反向推导出测试项描述和测试方法。

## 任务说明

测试项名称: {test_item_name}

测试用例如下:
{test_cases}

## 分析要求

请分析这些测试用例，观察以下规律：
1. 如果多个用例只是个别变量不同，但整体描述基本相同，应该总结为一条测试项描述和测试方法，但是这些用例之间不同的变量在测试项描述和测试方法中要一个不漏的体现出来
2. 如果用例的测试逻辑不同，应该总结为不同的测试项描述和测试方法
3. 测试项描述和测试方法的条目数必须一致
4. 测试项描述应该描述“要测试什么”
5. 测试方法应该描述“如何进行测试”
6. 当用例步骤中出现代码插桩、插装、埋点、打印日志、打印信息等开发辅助操作时，测试方法中不要保留具体实现细节，不要写明在哪个文件、哪个函数、哪一行插桩，也不要保留具体插入的代码内容
7. 对于代码插桩类步骤，测试方法要概括为“代码插桩，<插桩目的>”这样的表达，例如：步骤中出现“在 bit.c 文件 bit 函数 74 行插桩，插入 power.bit=1;”时，测试方法应概括为“代码插桩，设置主控板故障”
8. 如果代码插桩的作用是设置故障、模拟状态、打印调试信息、触发分支、构造异常条件等，应直接概括插桩目的，不展开底层实现细节

## 输出格式

请返回JSON格式的结果，包含两个对象：
- test_item_desc: 测试项描述对象（键为序号，值为内容）
- test_method: 测试方法对象（键为序号，值为内容）

示例格式：
```json
  {{
    "test_item_desc": {{
      "1": "1、验证系统在正常输入条件下的响应",
      "2": "2、验证系统在异常输入条件下的错误处理"
    }},
    "test_method": {{
      "1": "1、输入正常参数，观察系统输出是否符合预期",
      "2": "2、输入异常参数，验证系统是否正确报错"
    }}
  }}
```

## 注意事项

1. 测试项描述和测试方法都必须包含编号(如1、2、3、)	
2. 确保test_item_desc和test_method对象的键值对数量相同，且键的序号对应
3. 每条内容应该简洁明确
4. 只返回JSON格式，不要包含其他文字说明
