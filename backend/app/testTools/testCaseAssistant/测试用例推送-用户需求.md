# 测试用例推送工具 - 用户需求文档

## 一、功能概述

测试用例推送工具是一个基于AI的智能测试文档生成系统，旨在帮助测试人员快速生成标准化的需求分析表和测试用例单，大幅提升测试文档编写效率。

**流程说明**：

1. **文件导入阶段**：导入需求分析表/测试用例单Excel → 可选上传代码库zip
2. **功能选择**：
   - **路径1 - 组织资产推送**：选择产品类型和软件类型 → 从资产库匹配历史数据 → 自动填充测试项描述/测试方法或插入用例行 → 显示进度 → 下载推送后的Excel
   - **路径2 - AI智能生成**：选择要处理的行 → 选择生成场景 → AI生成内容
3. **需求分析表生成**：4个场景（初始化/通用功能/自检测/接口测试）→ AI生成测试项描述和测试方法 → 回填到表格
4. **测试用例单生成**：5个场景 → 代码定位（获取文件路径和行号）→ 自检测场景生成插桩代码 → AI生成用例内容 → 回填到表格
5. **在线编辑**：智能填充用例名称 + 格式调整 + 草稿管理 → 导出Excel

### 1.1 工具定位

本工具作为测试文档编写的辅助工具，解决以下核心痛点：
- **文档编写耗时**：手工编写需求分析表和测试用例单耗时耗力，效率低下
- **格式不统一**：不同测试人员编写的文档格式各异，难以标准化管理
- **内容质量参差**：缺乏经验的测试人员难以编写高质量的测试文档
- **资产复用困难**：历史项目的测试资产难以有效复用，重复劳动多

### 1.2 核心能力

**组织资产推送**：
- 从组织资产库中智能匹配历史测试数据
- 根据测试项名称自动填充需求分析表
- 根据测试项名称自动插入和填充测试用例
- 支持多种产品类型和软件类型的资产库

**AI智能生成**：
- 基于模板和上下文智能生成测试文档内容
- 支持需求分析表的4类生成场景
- 支持测试用例单的4类生成场景
- 自动定位代码位置，生成精确的测试步骤

**在线编辑**：
- 基于x-spreadsheet的在线Excel编辑器
- 支持导入/导出Excel文件
- 支持草稿保存和加载
- 支持右键菜单快捷操作

### 1.3 支持的文档类型

**需求分析表**：
- 包含测试项名称、需求子项描述、测试项描述、测试方法等字段
- 支持初始化、通用功能、自检测、接口测试等场景

**测试用例单**：
- 包含测试项名称、用例名称、测试描述、输入条件、预期结果等字段
- 支持初始化、通用功能、自检测、接口测试等场景

### 1.4 核心价值

- **效率提升80%**：通过AI自动生成和资产复用，大幅减少文档编写时间
- **质量保障**：基于标准模板和AI智能生成，确保文档质量和一致性
- **资产复用**：充分利用历史项目的测试资产，避免重复劳动
- **代码关联**：自动定位代码位置，生成精确的测试步骤和插桩代码

## 二、核心用户需求

### 需求1：组织资产推送，快速复用历史测试数据

**用户痛点**：
- 历史项目积累了大量测试文档，但难以有效复用
- 相似的测试项需要重复编写，浪费时间
- 不同项目的测试文档格式不统一，难以直接复用
- 缺乏统一的资产管理和推送机制

**解决方案**：通过组织资产库智能匹配和推送历史测试数据

#### 1.1 资产库管理

**需求描述**：
建立组织级的测试资产库，按产品类型和软件类型分类管理历史测试数据。

**资产库结构**：
- **产品类型**：转塔、对抗告警、光雷、吊舱等
- **软件类型**：每个产品类型下包含多个软件类型
- **资产内容**：
  - 需求分析表数据（测试项描述、测试方法）
  - 测试用例数据（用例名称、测试描述、输入条件、预期结果）

**数据来源**：
- 历史项目的测试文档
- 经过验证和标准化的测试数据
- 持续更新和维护

**实现方式**：
- 后端：`IntelligentExportService`智能导出服务
- 数据库：动态数据库管理模块
- 匹配规则：基于测试项名称的精确匹配或模糊匹配

**用户价值**：
- 充分利用历史测试资产
- 避免重复编写相同的测试内容
- 提升测试文档编写效率

#### 1.2 需求分析表推送

**需求描述**：
根据用户上传的需求分析表，从资产库中匹配测试项，自动填充测试项描述和测试方法。

**推送流程**：
1. 用户上传包含"需求分析表"sheet的Excel文件
2. 选择产品类型和软件类型
3. 系统从资产库中查询匹配的测试项数据
4. 根据测试项名称进行匹配：
   - 精确匹配：测试项名称完全相同
   - 模糊匹配：测试项名称包含关键词
5. 自动填充以下字段：
   - **测试项描述**（T列）：详细的测试项功能描述
   - **测试方法**（U列）：测试方法和步骤
6. 生成推送后的Excel文件供下载

**匹配规则**：
- 优先精确匹配：测试项名称完全一致
- 其次模糊匹配：测试项名称包含核心关键词
- 支持多对一匹配：一个测试项可能匹配多条资产数据

**实现方式**：
- 前端组件：`AssetReuseExportDialog.vue`
- 后端服务：`AssetReuseExportService`
- API接口：
  - `POST /asset-reuse-export/start`：启动推送任务
  - `GET /asset-reuse-export/progress/{task_id}`：查询推送进度
  - `GET /asset-reuse-export/download/{task_id}`：下载推送结果

**用户价值**：
- 快速填充需求分析表的核心字段
- 确保测试项描述和测试方法的标准化
- 减少手工编写时间

#### 1.3 测试用例单推送

**需求描述**：
根据用户上传的测试用例单，从资产库中匹配测试项，自动插入用例行并填充用例内容。

**推送流程**：
1. 用户上传包含"测试用例单"sheet的Excel文件
2. 选择产品类型和软件类型
3. 系统从资产库中查询匹配的测试用例数据
4. 根据测试项名称进行匹配
5. 在对应测试项下插入用例行
6. 自动填充以下字段：
   - **用例名称**（I列）：用例的简短名称
   - **测试描述**（L列）：详细的测试步骤描述
   - **输入条件**（P列）：测试的输入条件和前置条件
   - **预期结果**（Q列）：预期的测试结果
7. 生成推送后的Excel文件供下载

**插入策略**：
- 在测试项的第一行下方插入用例行
- 保持原有用例不变，新增用例追加在后面
- 自动调整行号和格式

**实现方式**：
- 前端组件：`AssetReuseExportDialog.vue`
- 后端服务：`AssetReuseExportService`
- 数据处理：`IntelligentExportService`

**用户价值**：
- 快速生成测试用例的基础框架
- 确保用例内容的完整性和标准化
- 大幅减少用例编写时间

#### 1.4 推送进度显示

**需求描述**：
实时显示资产推送的进度，让用户了解处理状态。

**进度信息**：
- 当前处理阶段：
  - 开始处理
  - 解析Excel文件
  - 匹配需求分析表数据
  - 匹配测试用例数据
  - 生成输出文件
  - 处理完成
- 进度百分比：0-100%
- 处理消息：当前正在执行的操作

**实现方式**：
- 前端：进度条组件（Element Plus Progress）
- 后端：通过回调函数更新进度
- 轮询机制：前端每秒查询一次进度

**用户价值**：
- 了解处理进度，避免焦虑等待
- 及时发现处理错误
- 提升用户体验

#### 1.5 推送结果下载

**需求描述**：
推送完成后，用户可以下载填充后的Excel文件。

**下载内容**：
- 原始Excel文件的所有sheet
- 需求分析表：已填充测试项描述和测试方法
- 测试用例单：已插入和填充用例行
- 保持原有格式和样式

**文件命名**：
- 格式：`[原文件名]_推送_[时间戳].xlsx`
- 示例：`测试文档_推送_20240101_120000.xlsx`

**实现方式**：
- 后端：生成Excel文件并存储到临时目录
- API：`GET /asset-reuse-export/download/{task_id}`
- 前端：点击下载按钮触发文件下载

**用户价值**：
- 获取完整的推送结果
- 可以在本地进一步编辑和完善
- 支持多次下载

### 需求2：AI智能生成测试文档，提升编写质量和效率

**用户痛点**：
- 从零开始编写测试文档耗时耗力
- 缺乏经验的测试人员难以编写高质量的测试内容
- 测试步骤描述不够详细和准确
- 难以定位代码位置和生成插桩代码

**解决方案**：通过AI智能生成测试文档内容，结合代码定位生成精确的测试步骤

#### 2.1 需求分析表生成

**需求描述**：
基于模板和上下文，使用AI智能生成需求分析表的测试项描述和测试方法。

**生成场景**：

**场景1：初始化**
- 适用：测试项名称包含"初始化"关键词
- 输入：
  - 测试项名称（如"SRIO初始化"）
  - 需求子项描述
  - 测试项描述模板（包含占位符xx、yy、zz等）
  - 测试方法模板
- AI任务：
  - 识别测试项中的关键对象（如SRIO）
  - 替换模板中的占位符
  - 生成完整的测试项描述和测试方法
- 输出：
  - 测试项描述：详细的功能描述
  - 测试方法：具体的测试步骤

**场景2：通用功能**
- 适用：常规功能测试项
- 输入：
  - 测试项名称
  - 需求子项描述
  - 当前测试项描述
  - 当前测试方法
  - 变量映射（xx、yy、zz等的具体值）
- AI任务：
  - 理解测试项的功能需求
  - 根据变量映射替换占位符
  - 优化和完善测试描述和方法
- 输出：
  - 优化后的测试项描述
  - 优化后的测试方法

**场景3：自检测**
- 适用：自检测相关的测试项
- 输入：

#### 2.3 代码定位功能

3. 用户在生成测试用例时粘贴代码片段
4. 系统分析代码片段：
   - 提取函数名
   - 提取关键代码行

5. 在代码库中搜索匹配的代码：
   - 按函数名搜索
   - 按代码行精确匹配
   - 按代码模式模糊匹配
6. 返回定位结果：
   - 文件路径（相对路径）
   - 行号范围
   - 函数名
   - 上下文代码

**定位工具**：

- `find_enclosing_function_in_file`：在文件中查找包含指定行的函数

  - 模糊匹配：去除空格和注释后匹配
  - 函数名匹配：按函数名查找

**用户价值**：
- 无需手工查找代码位置

#### 2.4 插桩代码生成

**需求描述**：
针对自检测场景，自动生成插桩代码，用于故障注入和检测。

**插桩流程**：
1. 定位代码文件和函数
2. 分析函数结构，找到插桩锚点：
   - 函数开始位置
   - 关键变量赋值后
   - 关键函数调用前后
   - 返回语句前
3. 生成插桩代码：
   - 故障注入代码
   - 故障检测代码
   - 日志输出代码
4. 将插桩代码嵌入测试描述中

**插桩示例**：
```c
// 原始代码
void init_srio() {
    srio_config_t config;
    config.baudrate = 9600;
    srio_init(&config);
}

// 插桩后
void init_srio() {
    srio_config_t config;
    config.baudrate = 9600;
    
    // 【插桩位置】故障注入
    if (fault_inject_enabled) {
        config.baudrate = 0; // 注入错误的波特率
    }
    
    srio_init(&config);
    
    // 【插桩位置】故障检测
    if (srio_status != SRIO_OK) {
        log_error("SRIO初始化失败");
    }
}
```

**实现方式**：
- 后端：`CaseDesignService`
- 插桩锚点查找：`find_instrumentation_anchor_in_function`
- AI生成：根据故障类别生成插桩代码

**用户价值**：
- 自动生成插桩代码，无需手工编写
- 确保插桩位置的准确性
- 提升自检测用例的质量

#### 2.5 模板占位符替换

**需求描述**：
支持在测试文档模板中使用占位符（xx、yy、zz、mm等），AI自动识别并替换为实际值。

**占位符类型**：
- **xx**：主要对象或变量（如SRIO、CAN、中断等）
- **yy**：次要对象或参数
- **zz**：第三个对象或参数
- **mm**：模块或功能名称
- **nn**、**kk**：其他占位符

**替换策略**：
1. **自动识别**：AI从测试项名称中提取关键词
   - 示例："SRIO初始化" → xx = "SRIO"
2. **用户指定**：用户通过变量映射指定占位符的值
   - 示例：`{"xx": "CAN", "yy": "波特率"}`
3. **智能替换**：AI根据上下文替换占位符
   - 保留模板结构
   - 替换占位符为实际值
   - 调整语句通顺性

**模板示例**：
```
测试项描述模板：
"验证xx初始化功能，包括yy配置和zz设置"

替换后：
"验证SRIO初始化功能，包括波特率配置和中断设置"
```

**实现方式**：
- 后端：`_apply_placeholders`方法
- AI识别：从测试项名称中提取关键词
- 正则替换：使用正则表达式替换占位符

**用户价值**：
- 提升模板的复用性
- 减少重复编写相似内容
- 确保文档的一致性

**组织资产推送流程**：
1. 用户上传Excel文件和选择产品类型/软件类型
2. 前端发送文件到后端
3. 后端解析Excel，提取测试项列表
4. 调用`IntelligentExportService`查询资产库
5. 根据测试项名称匹配资产数据
6. 填充需求分析表和测试用例单
7. 生成新的Excel文件并缓存
8. 前端轮询进度，完成后下载文件

**AI生成流程**：
1. 用户在表格中选择行，右键选择生成功能
2. 前端提取选中行的数据
3. 如果需要代码定位，用户粘贴代码片段
4. 前端发送数据到后端API
5. 后端调用AI客户端生成内容
6. 如果有代码片段，调用CodeLocator定位代码
7. AI根据模板、上下文和代码位置生成内容
8. 后端返回生成结果
9. 前端回填结果到表格对应单元格
10. 刷新表格显示

**代码定位流程**：
1. 用户上传代码库zip文件
2. 后端解压到临时目录
3. 用户粘贴代码片段
4. 后端提取函数名和关键代码行
5. 在代码库中搜索匹配的代码
6. 返回文件路径、行号、函数名
7. AI使用定位结果生成测试步骤

**进度同步**：
- 资产推送：后端通过回调函数更新进度，前端轮询查询
- AI生成：前端显示Loading遮罩，后端同步返回结果
- 批量处理：前端逐行调用API，实时更新进度文本

### 3.4 关键技术点

**x-spreadsheet集成**：
- 在线Excel编辑器，支持公式、样式、合并单元格等

**AI提示词工程**：

- 上下文注入：动态注入测试项信息、代码片段等
- 占位符替换：识别和替换xx、yy、zz等占位符

**代码定位算法**：
- 函数名匹配：提取函数名，在代码库中搜索
- 代码行匹配：精确匹配代码行内容
- 模糊匹配：去除空格和注释后匹配
- 上下文验证：验证匹配结果的上下文是否一致

**插桩锚点查找**：
- 函数结构分析：识别函数开始、结束、返回语句

**草稿管理**：
- 本地存储：使用localStorage保存草稿

- 版本管理：支持多个草稿版本

**错误处理**：
- API错误：统一的错误提示和日志记录
- AI生成失败：记录失败原因，支持重试
- 代码定位失败：提示用户检查代码片段或代码库

### 4.5 常见问题处理

#### 问题1：AI生成失败

**可能原因**：
- 网络连接问题
- AI服务暂时不可用
- 输入数据格式错误

**解决方法**：
- 检查网络连接
- 稍后重试
- 检查输入数据是否完整
- 查看后端日志获取详细错误信息

#### 问题2：代码定位失败

**可能原因**：
- 代码库未上传
- 代码片段不完整或不准确
- 代码库中不存在该代码

**解决方法**：
- 确认已上传代码库
- 检查代码片段是否完整
- 尝试粘贴更多的上下文代码
- 确认代码片段来自上传的代码库

#### 问题3：生成内容不符合预期

**可能原因**：
- 变量映射不准确
- 模板内容不合适
- AI理解偏差

**解决方法**：
- 调整变量映射，使用更准确的值
- 修改模板内容，提供更多上下文
- 重新生成，多次尝试
- 手工调整生成的内容

#### 问题4：Excel导入导出失败

**可能原因**：
- 文件格式不正确
- 文件损坏
- 浏览器兼容性问题

**解决方法**：
- 确认文件格式为.xlsx或.xls
- 尝试用Excel重新保存文件
- 更换浏览器（推荐Chrome或Edge）
- 检查文件大小是否过大

#### 问题5：草稿保存失败

**可能原因**：
- 浏览器本地存储已满
- 浏览器隐私模式
- 浏览器不支持localStorage

**解决方法**：
- 清理浏览器缓存和本地存储
- 退出隐私模式
- 更换浏览器
- 定期导出Excel文件作为备份
