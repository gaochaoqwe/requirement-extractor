需求分析表中的"软件需求描述"列和"需求子项描述"列是从**需求规格说明文档**中提取的，系统采用**多级优先级策略**来确保提取的准确性和效率。

## 二、标准化文档的作用

### 为什么优先使用标准化文档？

标准化文档具有以下优势：
1. **编号清晰**：每个章节标题都包含手动插入的编号（如 "3.2.1 用户身份验证功能"）
2. **匹配准确**：标题格式统一，避免了原始文档中可能存在的格式不一致问题
3. **提取稳定**：减少因Word自动编号失效导致的提取错误

### 如何查找标准化文档？

**代码位置**：`docx_requirement_parser.py` 第462-520行

### 算法步骤

#### 步骤1：解析文档章节结构（第62-110行）

```python
def _parse_chapter_structure(self, document_lines: List[str]) -> List[Dict]:
    """
    解析文档的章节结构
    
    识别章节编号格式：3.2.1, 3.2.1.1, 3.2.1.1.1 等
    """
    chapters = []
    
    for i, line in enumerate(document_lines):
        # 匹配章节编号格式 (如 3.2.1, 3.2.1.1, 3.2.1.1.1 等)
        chapter_match = re.match(r'^(\d+(?:\.\d+)*)\s+(.+)', line)
        if chapter_match:
            chapter_number = chapter_match.group(1)
            title = chapter_match.group(2).strip()
            level = len(chapter_number.split('.'))
            
            chapter_info = {
                'line_index': i,
                'chapter_number': chapter_number,  # "3.2.1"
                'title': title,                    # "用户身份验证功能"
                'level': level,                    # 3
                'has_children': False,
                'full_title': f"{chapter_number} {title}"
            }
            chapters.append(chapter_info)
    
    # 判断哪些章节有子章节
    for i, chapter in enumerate(chapters):
        if i < len(chapters) - 1:
            next_chapter = chapters[i + 1]
            if next_chapter['level'] > chapter['level']:
                chapter['has_children'] = True
    
    return chapters
```

```python
class RequirementMatcher:
    def is_requirement_name_match(self, heading: str, req_name: str) -> bool:
        """
        判断标题是否与需求名称匹配
        
        支持多种匹配模式：
        1. 完全匹配
        2. 包含匹配
        3. 去除标点后匹配
        4. 关键词匹配（75%相似度阈值）
        """
        
        # 1. 完全匹配
        if heading_clean == req_name_clean:
            return True
        
        # 2. 包含匹配
        if req_name_clean in heading_clean or heading_clean in req_name_clean:
            return True
        
        # 3. 去除编号后匹配
        # 匹配模式：3.2.1 用户身份验证功能 -> 用户身份验证功能
        heading_title_match = re.search(r'^\d+(\.\d+)*\s+(.+)$', heading_clean)
        if heading_title_match:
            heading_title = heading_title_match.group(2)
            if heading_title == req_name_clean or req_name_clean in heading_title:
                return True
        
        # 4. 关键词匹配（去除功能、模块等通用词后比较）
        heading_keywords = set(heading_clean.replace('功能', '').replace('模块', '').split())
        req_keywords = set(req_name_clean.replace('功能', '').replace('模块', '').split())
        
        # 如果有75%以上的关键词重叠，认为匹配
        if req_keywords and heading_keywords:
            intersection = heading_keywords & req_keywords
            similarity = len(intersection) / len(req_keywords)
            if similarity >= 0.75:
                return True
        
        return False
```

#### 步骤3：确定内容提取范围（第190-230行）

**核心算法**：从章节标题后提取到下一个同级或更高级章节之间的内容

```python
def _determine_content_range(self, chapter_structure: List[Dict], target_chapter: Dict):
    """
    确定内容提取的行范围
    
    实现算法：
    1. 基本算法：找到下一个同级或更高级章节
    2. 特殊处理：跳过有子章节的父章节（级别>=4）
    """
    start_line = target_chapter['line_index'] + 1  # 从标题下一行开始
    current_level = target_chapter['level']
    
    # 寻找结束位置
    for next_chapter in remaining_chapters:
        next_level = next_chapter['level']
        
        # 如果遇到同级或更高级的章节
        if next_level <= current_level:
            # 🌟 特殊处理：如果这个章节有子章节且级别>=4，继续寻找
            if next_level >= 4 and next_chapter['has_children']:
                continue  # 跳过这个有子章节的父章节
            else:
                end_line = next_chapter['line_index']
                break
    
    return start_line, end_line
```

#### 步骤4：解析结构化内容（第255-331行）

提取标准字段格式：

```python
def _parse_standard_fields(self, content: str) -> Dict:
    """
    解析标准字段格式
    
    支持格式：a) 标识号：, b) 说明：, c) 进入条件：等
    """
    field_patterns = {
        r'[a-h]\)\s*标识号[：:]\s*(.+?)(?=[a-h]\)|$)': 'identifier',
        r'[a-h]\)\s*说明[：:]\s*(.+?)(?=[a-h]\)|$)': 'description',
        r'[a-h]\)\s*进入条件[：:]\s*(.+?)(?=[a-h]\)|$)': 'entry_condition',
        r'[a-h]\)\s*输入[：:]\s*(.+?)(?=[a-h]\)|$)': 'input',
        r'[a-h]\)\s*输出[：:]\s*(.+?)(?=[a-h]\)|$)': 'output',
        r'[a-h]\)\s*处理[：:]\s*(.+?)(?=[a-h]\)|$)': 'processing',
        r'[a-h]\)\s*性能[：:]\s*(.+?)(?=[a-h]\)|$)': 'performance',
        r'[a-h]\)\s*约束[与和]?限制[：:]\s*(.+?)(?=[a-h]\)|$)': 'constraints'
    }
    
    for pattern, field_name in field_patterns.items():
        match = re.search(pattern, content, re.DOTALL | re.IGNORECASE)
        if match:
            fields[field_name] = match.group(1).strip()
    
    return fields
```

**提取到的字段对应关系**：

| 文档中的字段 | 数据库字段 | 需求分析表列名 |
|------------|-----------|--------------|
| a) 标识号   | identifier | -            |
| b) 说明     | description | **软件需求描述** |
| c) 进入条件 | entry_condition | **需求子项描述**的一部分 |
| d) 输入     | input | **需求子项描述**的一部分 |
| e) 输出     | output | **需求子项描述**的一部分 |
| f) 处理     | processing | **需求子项描述**的一部分 |
| g) 性能     | performance | **需求子项描述**的一部分 |
| h) 约束与限制 | constraints | **需求子项描述**的一部分 |

**注意**：
- **软件需求描述** = `description` 字段（b) 说明）
- **需求子项描述** = 其他字段的组合（c-h字段）

## 五、关键技术点总结

### 1. 为什么使用标准化文档？

✅ **匹配准确率最高**：
- 标准化文档的标题格式统一（都包含手动编号）
- 避免了Word自动编号可能失效的问题
- 减少了文本匹配的不确定性

### 2. 匹配算法核心

**四种匹配策略**（按优先级）：
1. 精确匹配
2. 清理后匹配（去标点）
3. 包含匹配
4. 关键词匹配（75%相似度）

### 3. 内容提取范围算法

**基本原则**：
- 从章节标题后的第一行开始
- 提取到下一个同级或更高级章节之前
- 特殊处理：跳过有子章节的四级及以上父章节

### 4. 字段解析

**使用正则表达式**提取标准格式：
```
a) 标识号：XXX
b) 说明：XXX
c) 进入条件：XXX
```

## 七、常见问题

### Q1: 如果没有标准化文档会怎样？

A: 系统会自动回退到其他提取方法（位置缓存、智能章节提取器等），不会影响功能，但准确率可能略低。

### Q2: 字段匹配不到怎么办？

A: 系统有验证机制，如果提取的关键字段少于4个，会将所有内容放入 `description` 字段，确保不丢失信息。

### Q3: 如何提高提取准确率？

A: 
1. ✅ 确保文档标准化成功完成
2. ✅ 使用标准的字段格式（a) 标识号、b) 说明等）
3. ✅ 章节标题包含完整的编号和名称

### Q4: 为什么编辑时看到的章节名称更准确？

A: 因为编辑时使用的是后端生成的 `full_text` 字段，这是从文档中直接读取的标准化内容，而不是前端拼接的。
