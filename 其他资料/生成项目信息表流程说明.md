# 生成项目信息表流程说明

## 📋 流程概述

生成项目信息表是配置项测试工具的**步骤1**，用于生成项目基本信息和软件配置信息的Excel表单。

## 🔄 完整流程

### 1. 前置条件检查

```
用户点击"开始生成"按钮
    ↓
前端检查：
  ✓ 是否已上传需求文档 (sessionId存在)
  ✓ 是否填写了基本信息 (表单验证)
    ↓
如果检查通过 → 开始生成
如果检查失败 → 显示错误提示
```

### 2. 前端数据准备

**文件位置**: `frontend_vue/src/views/danamicTest/ConfigurationItem/ConfigurationTestView.vue`

**函数**: `generateStep1()` (第3205行)

**步骤**:
1. 验证表单数据
2. 准备基本信息和可选信息
3. 调用服务接口

**传递的数据**:

```javascript
// 基本信息 (必填)
{
  testManager: '李佳真',        // 测试主管
  testPersonnel: '王刚(外协)',  // 测试人员
  developer: '雷宇博',          // 开发人员 (申请人)
  softwareName: '超级搜索雷达',  // 软件名称
  softwareVersion: 'V1.0',     // 软件版本
  softwareId: '20250909',      // 软件标识
  domain: '火控',              // 所属领域 (由申请部门推断)
  productType: '转塔',         // 组件
  detectorFlag: '有检测仪'     // 检测仪标识
}

// 可选信息
{
  aircraftModel: '雷霆',            // 机型
  projectDirector: '周山明',        // 项目总师
  developmentDepartment: '总体部',  // 申请部门
  chiefDesigner: '任伟霆',         // 主任设计师
  projectManager: '葛飞鸟'         // 项目主管
}
```

### 3. 服务层调用

**文件位置**: `frontend_vue/src/services/configurationItemService.js`

**函数**: `generateProjectInfo()` (第309行)

**操作**:
1. 将数据封装成FormData
2. 发送POST请求到后端API: `/api/dynamic-test/configuration/generate-step1-project-info`
3. 返回任务ID

### 4. 后端API处理

**文件位置**: `backend/app/danamicTest/ConfigurationItem/api/form_api.py`

**端点**: `@router.post("/generate-step1-project-info")` (第314行)

**接收参数**:
- session_id: 会话ID
- 基本信息字段 (test_manager, test_personnel, developer, 等)
- 可选信息字段 (aircraft_model, project_director, 等)
- code_lines: 代码行数 (可选)

**处理流程**:
1. 接收所有表单数据
2. 验证session_id
3. 创建后台任务
4. 返回task_id

### 5. 后台任务执行

**异步执行以下步骤**:

```
后台任务启动
    ↓
1. 加载会话状态
    ↓
2. 查找需求文档和测试需求目录
    ↓
3. 调用项目信息生成服务
    ↓
4. 生成Excel文件
   - 项目信息表
   - 软件配置项表
    ↓
5. 保存生成的文件
    ↓
6. 更新任务状态为"已完成"
    ↓
7. 记录生成的文件列表
```

### 6. 前端轮询状态

**函数**: `pollStepStatus()` (ConfigurationTestView.vue 第3136行)

**轮询逻辑**:
```
每2秒查询一次任务状态
    ↓
任务状态 = 'running' → 继续轮询
任务状态 = 'completed' → 停止轮询，显示成功
任务状态 = 'failed' → 停止轮询，显示错误
```

### 7. 生成完成

**前端显示**:
- ✅ 步骤1标记为"已完成"
- 📁 显示生成的文件列表
- 💾 提供文件下载按钮

## ⚠️ 常见问题

### Q1: 所属领域没有填充

**原因**: OCR文本中没有"申请部门"字段

**解决**: 
1. 确保OCR文本包含"申请部门XXX"
2. 查看控制台日志，确认是否识别了申请部门
3. 手动填写所属领域

### Q2: 测试主管和测试人员是空的

**原因**: 所属领域推断失败

**解决**:
1. 检查申请部门是否正确
2. 检查部门名称是否在映射表中
3. 手动填写测试主管和测试人员

### Q3: 软件名称、版本、标识没有填充

**原因**: 这些字段由需求文档提取，不是OCR识别

**解决**:
1. 确保已上传需求规格说明文档
2. 查看上传时的提示信息
3. 如果提取失败，手动填写

### Q4: 生成任务失败

**原因**: 多种可能

**排查步骤**:
1. 查看前端控制台错误
2. 查看后端日志
3. 检查session_id是否有效
4. 检查必填字段是否都有值

## 📝 完整示例

### 用户操作流程

```
1. 上传需求文档 (.docx)
   ✓ 自动提取软件名称、版本、标识
   ✓ 自动提取测试需求目录

2. 粘贴OCR识别结果
   ✓ 自动填充申请人、机型、部门等
   ✓ 自动推断所属领域
   ✓ 自动推断测试主管和测试人员

3. 检查表单
   ✓ 确认所有必填字段都有值
   ✓ 手动修正错误的字段

4. 点击"开始生成"
   ✓ 等待生成完成 (通常10-30秒)
   ✓ 下载生成的Excel文件

5. 修改并上传
   ✓ 下载Excel文件
   ✓ 手动修改内容
   ✓ 上传修改后的文件
   ✓ 继续步骤2
```
