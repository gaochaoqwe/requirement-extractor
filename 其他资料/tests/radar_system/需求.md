# 雷达仿真系统软件需求规格说明书

## 1 引言

### 1.1 目的

本文档描述雷达仿真系统（Radar Simulation System）的软件功能需求，供系统设计、开发与测试人员使用。

### 1.2 范围

本系统为嵌入式 C 语言实现的雷达仿真软件，涵盖雷达核心控制、信号采集与处理、目标跟踪三大模块，支持扫描模式与跟踪模式的工作切换。

### 1.3 术语与缩略语

| 术语 | 说明 |
|------|------|
| FFT | 快速傅里叶变换（Fast Fourier Transform） |
| RCS | 雷达截面积（Radar Cross Section） |
| 航迹 | 雷达对目标运动轨迹的持续记录 |
| 关联门限 | 判断测量值与航迹是否属于同一目标的距离阈值 |

---

## 2 系统概述

雷达仿真系统由三个核心模块组成：

- **雷达系统核心模块**（`radar_system`）：负责系统状态管理、信号数据处理与目标列表维护。
- **信号处理模块**（`signal_processor`）：负责原始信号采集、滤波去噪及 FFT 频域变换。
- **目标跟踪模块**（`target_tracker`）：负责航迹管理、目标关联与位置预测。

系统工作流程：初始化 → 启动扫描 → 信号采集与处理 → 目标跟踪更新 → （可选）切换跟踪模式 → 资源清理。

## 3 功能需求

### 3.1 系统初始化与资源管理

#### 3.1.1 系统初始化功能

a) **标识号**：REQ-1.1

b) **说明**：系统启动时须按顺序依次初始化雷达核心模块、信号处理模块和目标跟踪模块，确保各模块依赖关系正确。

c) **进入条件**：系统上电或重启，主程序开始执行。

d) **输入**：
- 雷达配置参数（`RadarConfig`），包括：
  - 扫描频率（`scan_frequency`，单位：Hz）
  - 最大探测距离（`max_range`，单位：米）
  - 最小探测距离（`min_range`，单位：米）
  - 最大跟踪目标数（`max_targets`）
  - 检测阈值（`threshold`，范围：0.0～1.0）
  - 日志文件路径（`log_file`）

e) **输出**：
- 初始化成功：返回 0，系统进入 `RADAR_STATE_IDLE` 状态。
- 初始化失败：返回 -1，并向标准错误输出错误信息。

f) **处理**：
1. 验证 `RadarConfig` 指针非 NULL，且 `max_targets` 为正整数。
2. 按顺序执行：`radar_init()` → `signal_processor_init()` → `tracker_init()`。
3. `radar_init()` 内部：复制配置参数、分配目标列表内存、打开日志文件、将状态置为 `RADAR_STATE_IDLE`。
4. `signal_processor_init()` 内部：分配 FFT 缓冲区（大小为 `MAX_SAMPLES × 2` 个 `double`）、初始化滤波器参数、置初始化标志为 1。
5. `tracker_init()` 内部：分配航迹数组内存、将所有航迹初始化为非激活状态。
6. 若任一步骤失败，须逆序清理已成功初始化的模块后返回 -1。

g) **性能**：
- 初始化总耗时 ≤ 500 ms。

h) **约束与限制**：
- 初始化顺序必须严格为：`radar_init` → `signal_processor_init` → `tracker_init`，不可颠倒。
- `max_targets` 必须为正整数，否则初始化失败。
- 日志文件打开失败时，系统初始化应返回失败。

---

#### 3.1.2 系统资源清理功能

a) **标识号**：REQ-1.2

b) **说明**：系统退出时须按初始化的相反顺序依次清理各模块资源，确保无内存泄漏和文件句柄泄漏。

c) **进入条件**：系统正常退出或发生不可恢复错误。

d) **输入**：无。

e) **输出**：
- 所有动态内存已释放，文件句柄已关闭，全局状态已重置。
- 系统状态置为 `RADAR_STATE_SHUTDOWN`。

f) **处理**：
1. 按顺序执行：`tracker_cleanup()` → `signal_processor_cleanup()` → `radar_cleanup()`。
2. `tracker_cleanup()`：释放航迹数组内存，重置 `g_max_tracks`、`g_track_count` 为 0。
3. `signal_processor_cleanup()`：释放 FFT 缓冲区，重置初始化标志为 0。
4. `radar_cleanup()`：释放目标列表内存、关闭日志文件（`fclose`）、重置所有全局状态变量，将系统状态置为 `RADAR_STATE_SHUTDOWN`。

g) **性能**：
- 清理总耗时 ≤ 200 ms。

h) **约束与限制**：
- 清理顺序必须与初始化顺序相反。
- 所有指针在释放后须置 `NULL`，防止悬空指针。
- 日志文件必须在 `radar_cleanup()` 中显式关闭，不得遗漏。

---

### 3.2 雷达扫描控制

#### 3.2.1 启动雷达扫描功能

a) **标识号**：REQ-2.1

b) **说明**：将雷达从空闲状态切换到扫描状态，开始主动探测并初始化目标列表。

c) **进入条件**：系统已完成初始化，当前状态为 `RADAR_STATE_IDLE`。

d) **输入**：无（使用已配置的 `RadarConfig` 参数）。

e) **输出**：
- 成功：返回 0，系统状态切换为 `RADAR_STATE_SCANNING`，日志记录启动事件。
- 失败：返回 -1，状态不变。

f) **处理**：
1. 检查当前状态是否为 `RADAR_STATE_IDLE`，若不是则返回 -1。
2. 清空目标列表（`g_target_count = 0`，`memset` 清零）。
3. 将系统状态切换为 `RADAR_STATE_SCANNING`。
4. 向日志文件写入启动记录（含时间戳）。

g) **性能**：
- 状态切换延迟 ≤ 10 ms。

h) **约束与限制**：
- 只允许从 `RADAR_STATE_IDLE` 状态启动扫描，其他状态调用须返回错误。
- 写日志前须确认日志文件句柄非 `NULL`。

---

#### 3.2.2 停止雷达扫描功能

a) **标识号**：REQ-2.2

b) **说明**：停止雷达扫描，保存当前目标数据，将系统切回空闲状态。

c) **进入条件**：当前状态为 `RADAR_STATE_SCANNING`。

d) **输入**：无。

e) **输出**：
- 成功：返回 0，系统状态切换为 `RADAR_STATE_IDLE`，当前目标列表数据被保存，日志记录停止事件。
- 失败：返回 -1，状态不变。

f) **处理**：
1. 检查当前状态是否为 `RADAR_STATE_SCANNING`，若不是则返回 -1。
2. 将当前目标列表数据持久化保存（至少保证目标计数不被清零）。
3. 将系统状态切换为 `RADAR_STATE_IDLE`。
4. 向日志文件写入停止记录（含时间戳）。

g) **性能**：
- 状态切换延迟 ≤ 10 ms。

h) **约束与限制**：
- 停止前须完整保存当前扫描结果，不得丢失目标数据。
- 只允许从 `RADAR_STATE_SCANNING` 状态调用。

---

#### 3.2.3 切换跟踪模式功能

a) **标识号**：REQ-2.3

b) **说明**：将雷达从扫描模式切换到对指定目标的专项跟踪模式，停止对其余目标的维护。

c) **进入条件**：当前状态为 `RADAR_STATE_SCANNING`，且指定目标 ID 存在于目标列表中。

d) **输入**：
- 目标 ID（`target_id`，`uint32_t`）

e) **输出**：
- 成功：返回 0，系统状态切换为 `RADAR_STATE_TRACKING`，日志记录切换事件。
- 失败（目标不存在或状态不合法）：返回 -1。

f) **处理**：
1. 检查当前状态是否为 `RADAR_STATE_SCANNING`，若不是则返回 -1。
2. 调用 `radar_stop_scan()` 停止扫描模式。
3. 在目标列表中查找 `target_id`，若未找到则返回 -1。
4. 将非指定目标的列表项清除，仅保留锁定目标。
5. 将系统状态切换为 `RADAR_STATE_TRACKING`。
6. 向日志文件写入切换记录（含时间戳和目标 ID）。

g) **性能**：
- 模式切换延迟 ≤ 50 ms。

h) **约束与限制**：
- 必须先停止扫描（`radar_stop_scan`）后再切换跟踪，不得跳过。
- 切换后须清理所有非锁定目标，释放相关资源。

---

### 3.3 信号处理

#### 3.3.1 原始信号采集功能

a) **标识号**：REQ-3.1

b) **说明**：从硬件（或仿真）采集一帧原始雷达信号数据，形成带时间戳的信号结构体，供后续处理使用。

c) **进入条件**：信号处理器已初始化（`g_is_initialized == 1`）。

d) **输入**：无（从硬件或仿真数据源获取）。

e) **输出**：
- 成功：返回 `SignalData*` 指针，包含：
  - `samples`：采样数组（`MAX_SAMPLES` 个 `double`）
  - `sample_count`：采样点数（= `MAX_SAMPLES`）
  - `timestamp`：当前时间戳
  - `frequency`：载波频率（10 GHz）
- 失败：返回 `NULL`。

f) **处理**：
1. 检查初始化标志，未初始化则返回 `NULL`。
2. 分配 `SignalData` 结构内存。
3. 分配采样数组内存（`MAX_SAMPLES` 个 `double`）。
4. 填充时间戳与频率信息。
5. 生成仿真采样数据（含多频正弦叠加与随机噪声）。
6. 返回 `SignalData*`；调用者须通过 `signal_release()` 释放。

g) **性能**：
- 单帧采集耗时 ≤ 10 ms。
- 最大采样点数：`MAX_SAMPLES = 1024`。

h) **约束与限制**：
- 返回的内存由调用者负责通过 `signal_release()` 释放，不得直接 `free`。

---

#### 3.3.2 信号滤波功能

a) **标识号**：REQ-3.2

b) **说明**：对原始采样信号应用移动平均低通滤波器，去除高频噪声，原地更新采样数据，不改变 `SignalData` 指针。

c) **进入条件**：`signal_acquire()` 已成功返回有效的 `SignalData`。

d) **输入**：
- `SignalData*`（含原始采样数据）

e) **输出**：
- 成功：返回 0，`signal->samples` 内容被滤波后数据原地替换（指针不变）。
- 失败：返回 -1。

f) **处理**：
1. 验证输入指针及 `samples` 非 `NULL`。
2. 分配临时缓冲区用于存储滤波结果。
3. 对每个采样点，取以其为中心、窗口大小为 `FILTER_WINDOW_SIZE`（= 5）的移动平均值；边界处截断窗口范围（`j` 须满足 `0 ≤ j < sample_count`）。
4. 将滤波结果写回 `signal->samples`（原地覆盖，**不替换指针**）。
5. 释放临时缓冲区。

g) **性能**：
- 1024 点滤波耗时 ≤ 5 ms。

h) **约束与限制**：
- 必须原地修改 `samples` 数组内容，不得替换 `signal->samples` 指针（否则导致原内存泄漏）。
- 窗口边界须做越界保护，不得访问负数索引。
- 滤波后不得有内存泄漏。

---

#### 3.3.3 FFT 频域变换功能

a) **标识号**：REQ-3.3

b) **说明**：将滤波后的时域信号转换为频域，计算各频率分量幅度，结果写回 `signal->samples`，供目标检测使用。

c) **进入条件**：`signal_filter()` 已对该帧信号完成滤波处理。

d) **输入**：
- 滤波后的 `SignalData*`

e) **输出**：
- 成功：返回 0，`signal->samples` 被频域幅度谱替换，`sample_count` 不变。
- 失败：返回 -1。

f) **处理**：
1. 验证输入指针及 `samples` 非 `NULL`，FFT 缓冲区已分配。
2. 将采样数据复制到全局 FFT 缓冲区（实部 = `samples[i]`，虚部 = 0）。
3. 执行离散傅里叶变换，计算各频率点实部幅度（`fabs(real_part)`）。
4. 将幅度谱写回 `signal->samples`，`sample_count` 保持不变。

g) **性能**：
- 1024 点 FFT 耗时 ≤ 50 ms。

h) **约束与限制**：
- 必须在 `signal_filter()` 之后调用，不得对未滤波数据执行 FFT。
- 全局 FFT 缓冲区为单例，不支持多线程并发调用。
- `sample_count` 在 FFT 前后保持不变。

---

#### 3.3.4 信号数据释放功能

a) **标识号**：REQ-3.4

b) **说明**：释放由 `signal_acquire()` 分配的 `SignalData` 结构及其采样数组，防止内存泄漏和悬空指针。

c) **进入条件**：`SignalData*` 已不再使用（处理流程结束）。

d) **输入**：
- 待释放的 `SignalData*`

e) **输出**：无（`void`）。副作用：相关内存已释放，调用者持有的指针应置 `NULL`。

f) **处理**：
1. 若传入指针为 `NULL`，直接返回。
2. 若 `signal->samples` 非 `NULL`，释放采样数组内存。
3. 释放 `SignalData` 结构本身内存。
4. 调用方须在调用后将自身指针置 `NULL`（防止悬空指针）。

g) **性能**：
- 释放耗时 ≤ 1 ms。

h) **约束与限制**：
- 不得重复释放同一 `SignalData`。
- `signal_filter()` 不得替换 `samples` 指针，否则将导致释放错误内存。

---

### 3.4 目标检测与处理

#### 3.4.1 信号数据处理与目标提取功能

a) **标识号**：REQ-4.1

b) **说明**：对完成 FFT 变换的信号逐采样点进行目标检测，提取满足阈值且在有效距离范围内的目标，更新全局目标列表，且不超过最大目标数限制。

c) **进入条件**：`signal_fft_transform()` 已完成，系统处于 `RADAR_STATE_SCANNING` 或 `RADAR_STATE_TRACKING` 状态。

d) **输入**：
- 经 FFT 处理的 `SignalData*`
- 系统配置：`threshold`、`min_range`、`max_range`、`max_targets`

e) **输出**：
- 成功：返回 0，全局目标列表 `g_target_list` 更新，日志记录本次检测到的目标数。
- 失败：返回 -1。

f) **处理**：
1. 验证 `signal` 及 `signal->samples` 非 `NULL`。
2. 遍历所有采样点，取幅度值。
3. 若幅度 < `g_config.threshold`，跳过。
4. 计算对应距离（`distance = i × 100.0` 米）。
5. 若距离 < `min_range` 或距离 > `max_range`，跳过（范围外目标不处理）。
6. 若当前目标数已达 `max_targets`，停止处理。
7. 构造 `Target` 结构体并追加至 `g_target_list`，`g_target_count` 加 1。
8. 向日志写入本次处理结果。

g) **性能**：
- 1024 采样点处理耗时 ≤ 20 ms。

h) **约束与限制**：
- 目标总数不得超过 `max_targets`（默认 50），超出须停止追加。
- 有效距离范围：`min_range`（默认 1000 m）≤ distance ≤ `max_range`（默认 100000 m）。
- 检测阈值默认值：0.3。

---

#### 3.4.2 目标列表查询功能

a) **标识号**：REQ-4.2

b) **说明**：返回当前所有有效目标，自动过滤超过 5 秒未更新的超时目标，更新目标计数。

c) **进入条件**：系统已初始化且目标列表存在。

d) **输入**：
- `count`：整数指针，用于接收有效目标数量。

e) **输出**：
- 成功：返回 `Target*` 指针及有效目标数（通过 `count` 输出）。
- `count` 指针为 `NULL` 时：返回 `NULL`。

f) **处理**：
1. 验证 `count` 指针非 `NULL`。
2. 获取当前时间戳。
3. 遍历目标列表，保留 `current_time - last_update ≤ 5` 秒的目标（过滤超时目标）。
4. 将有效目标紧凑排列至列表前部，更新 `g_target_count`。
5. 将 `g_target_count` 写入 `*count` 并返回 `g_target_list`。

g) **性能**：
- 查询耗时 ≤ 5 ms（50 目标规模）。

h) **约束与限制**：
- 超时判定阈值为 5 秒（`current_time - last_update > 5` 为超时）。
- 返回指针指向内部静态数组，调用者不得释放。
- 若需线程安全，须在调用前后加互斥锁保护。

---

### 3.5 目标跟踪

#### 3.5.1 目标跟踪更新功能

a) **标识号**：REQ-5.1

b) **说明**：将本次检测到的目标与已有航迹进行关联，更新航迹状态，按规则创建新航迹或删除丢失航迹，并对所有航迹年龄加 1。

c) **进入条件**：目标跟踪器已初始化，每次信号处理完成后调用（包括目标数为 0 的情况）。

d) **输入**：
- `targets`：当前帧检测目标数组
- `count`：目标数量（可为 0）

e) **输出**：
- 成功：返回 0，航迹列表完成更新。
- 失败：返回 -1。

f) **处理**：
1. 验证输入（`targets` 非 `NULL` 或 `count == 0`，`count ≥ 0`）。
2. 对每个输入目标，遍历所有激活航迹，计算位置差（距离差与方位角差的欧氏距离），找到距离最近且在 `ASSOCIATION_THRESHOLD`（50 m）内的航迹进行关联（全局最近邻算法）。
3. 关联成功：更新航迹位置、计算并更新速度（`(新位置 - 旧位置) / 时间差`），`hit_count` 加 1，`miss_count` 置 0。
4. 未关联目标：暂存候选，当同一目标连续出现 3 次后，创建新航迹。
5. 未被关联的激活航迹：`miss_count` 加 1，`hit_count` 置 0；`miss_count ≥ 5` 时将航迹设为非激活，`g_track_count` 减 1。
6. 所有激活航迹 `age` 加 1。
7. 无论是否检测到目标，均须执行步骤 5、6，保证航迹状态连续更新。

g) **性能**：
- 50 目标 × 50 航迹关联耗时 ≤ 10 ms。

h) **约束与限制**：
- 最大航迹数由 `tracker_init()` 的 `max_targets` 参数决定（默认 50）。
- 新航迹须连续出现 3 次才能确立，避免虚假航迹。
- 丢失判定阈值：`miss_count ≥ 5`。
- 每次信号处理后均须调用，不得仅在检测到目标时才调用。

---

#### 3.5.2 目标位置预测功能

a) **标识号**：REQ-5.2

b) **说明**：根据指定目标的当前位置和速度，使用匀速直线运动模型预测其未来位置，并验证结果合理性。

c) **进入条件**：目标跟踪器已初始化，指定目标的航迹处于激活状态。

d) **输入**：
- `target_id`：目标 ID（`uint32_t`）
- `delta_time`：预测时间间隔（秒，`double`）
- `pred_distance`：输出预测距离的指针
- `pred_azimuth`：输出预测方位角的指针

e) **输出**：
- 成功：返回 0，`*pred_distance` 和 `*pred_azimuth` 被赋值为预测结果。
- 失败（航迹不存在或输出指针为 `NULL`）：返回 -1。

f) **处理**：
1. 验证 `pred_distance`、`pred_azimuth` 非 `NULL`。
2. 在激活航迹中查找 `target_id`，未找到则返回 -1。
3. 计算预测距离：`*pred_distance = position[0] + velocity[0] × delta_time`。
4. 计算预测方位角：`*pred_azimuth = position[1] + velocity[1] × delta_time`。
5. 验证 `*pred_distance ≥ 0`，若为负值则修正为 0。

g) **性能**：
- 单目标预测耗时 ≤ 1 ms。

h) **约束与限制**：
- 速度信息须由 `tracker_update()` 正确计算，若速度为 0 则预测结果退化为当前位置。
- 预测距离不得为负值。

---

#### 3.5.3 测量数据与航迹关联功能

a) **标识号**：REQ-5.3

b) **说明**：将新一帧测量数据与所有激活航迹的预测位置进行全局最近邻关联，返回成功关联数量。

c) **进入条件**：目标跟踪器已初始化，存在激活航迹。

d) **输入**：
- `measurements`：测量目标数组
- `meas_count`：测量目标数量

e) **输出**：
- 成功：返回成功关联的数量（≥ 0）。
- 失败：返回 -1。

f) **处理**：
1. 验证输入参数（`measurements` 非 `NULL`，`meas_count ≥ 0`）。
2. 对每条激活航迹，调用 `tracker_predict_position()` 获取预测位置。
3. 计算每个测量值与各航迹预测位置的欧氏距离。
4. 使用全局最近邻算法，为每个测量值选择距离最近且在 `ASSOCIATION_THRESHOLD` 内的航迹进行关联。
5. 统计并返回成功关联的总数。

g) **性能**：
- 50 测量 × 50 航迹关联耗时 ≤ 10 ms。

h) **约束与限制**：
- 必须使用预测位置（非当前位置）进行关联，以适应高速运动目标。
- 关联门限：`ASSOCIATION_THRESHOLD = 50.0` m。
- 每个测量值最多关联一条航迹，每条航迹最多关联一个测量值。

#### 3.5.4 航迹质量评估功能

a) **标识号**：REQ-5.4

b) **说明**：计算指定目标的航迹质量分数（0～100），用于判断是否切换到专项跟踪模式。

c) **进入条件**：目标跟踪器已初始化，指定目标航迹处于激活状态。

d) **输入**：
- `target_id`：目标 ID（`uint32_t`）

e) **输出**：
- 激活航迹：返回质量分数（整数，0～100）。
- 航迹年龄为 0：返回 0。
- 非激活或不存在：返回 -1。

f) **处理**：
1. 在激活航迹中查找 `target_id`，未找到返回 -1。
2. 若航迹年龄 `age == 0`，返回 0。
3. 计算质量分数：`quality = (hit_count × 100) / age`（整数除法）。
4. 返回 `quality`（范围 0～100）。

g) **性能**：
- 单次查询耗时 ≤ 1 ms。

h) **约束与限制**：
- 计算公式须为 `(hit_count × 100) / age`，不得写成 `hit_count / (age × 100)`（后者导致结果趋近于 0）。
- 航迹年龄为 0 时须特判，不得执行除以 0 操作。
- 质量分数 > 80 时，系统应触发切换跟踪模式的逻辑。

### 3.6 主控流程

#### 3.6.1 扫描主循环功能

a) **标识号**：REQ-6.1

b) **说明**：系统在扫描模式下执行固定次数的信号处理循环，每次循环完整执行信号采集、滤波、FFT、目标处理、跟踪更新全流程，并在发现高质量目标时触发模式切换。

c) **进入条件**：系统已完成初始化，`radar_start_scan()` 调用成功。

d) **输入**：
- 扫描周期数（`SCAN_CYCLES = 10`）
- 每次循环间隔（1 秒）

e) **输出**：
- 控制台输出每个扫描周期的进度和检测结果。
- 日志记录各周期的信号处理与目标检测结果。
- 若发现高质量目标（质量分数 > 80），输出切换提示并进入跟踪模式。

f) **处理**：
1. 循环执行 `SCAN_CYCLES`（= 10）次：
   - 调用 `signal_acquire()` 采集信号，失败则 `continue`。
   - 调用 `signal_filter()` 对信号滤波。
   - 调用 `signal_fft_transform()` 执行 FFT 变换。
   - 调用 `radar_process_signal()` 提取目标。
   - 调用 `signal_release()` 释放信号内存。
   - 调用 `radar_get_targets()` 获取目标列表。
   - 无论目标数是否为 0，均调用 `tracker_update()` 更新航迹。
   - 遍历目标，调用 `tracker_get_track_quality()` 评估质量；若质量 > 80，先调用 `radar_stop_scan()`，再调用 `radar_switch_to_tracking()` 切换模式并退出循环。
2. 循环结束后若仍处于扫描状态，调用 `radar_stop_scan()`。

g) **性能**：
- 单次循环总耗时 ≤ 1100 ms（含 1 秒间隔）。
- 信号处理子流程（采集 + 滤波 + FFT + 目标提取）耗时 ≤ 100 ms。

h) **约束与限制**：
- 信号处理流程须严格按 acquire → filter → fft → process 顺序执行，不得跳过 filter 步骤。
- `tracker_update()` 须在每个周期调用，不得仅在有目标时才调用。
- 切换跟踪模式前须先停止扫描，不得直接调用 `radar_switch_to_tracking()`。

## 5 系统状态机

雷达系统共有以下五种状态，状态转换须遵循如下规则：

```
IDLE ──radar_start_scan()──→ SCANNING
SCANNING ──radar_stop_scan()──→ IDLE
SCANNING ──radar_switch_to_tracking()──→ TRACKING
TRACKING ──（停止跟踪）──→ IDLE
ANY ──（不可恢复错误）──→ ERROR
ANY ──（radar_cleanup）──→ SHUTDOWN
```

| 状态 | 枚举值 | 说明 |
|------|--------|------|
| 空闲 | `RADAR_STATE_IDLE` | 初始化完成后的默认状态 |
| 扫描中 | `RADAR_STATE_SCANNING` | 主动搜索目标 |
| 跟踪中 | `RADAR_STATE_TRACKING` | 专项跟踪锁定目标 |
| 错误 | `RADAR_STATE_ERROR` | 系统发生不可恢复错误 |
| 已关闭 | `RADAR_STATE_SHUTDOWN` | 资源清理完成，系统已停止 |

## 6 非功能需求

### 6.1 性能需求

- 信号处理全流程（采集 + 滤波 + FFT + 目标提取）耗时 ≤ 100 ms/帧。
- 50 目标规模下，航迹更新与关联耗时 ≤ 10 ms/帧。
- 系统初始化总耗时 ≤ 500 ms。
- 系统资源清理总耗时 ≤ 200 ms。

### 6.2 可靠性需求

- 所有动态内存分配后须检查返回值，分配失败须返回错误码并清理已分配资源。
- 所有指针在释放后须置 `NULL`，防止悬空指针和重复释放。
- 日志文件句柄在 `radar_cleanup()` 中须显式关闭。
- 系统在任何模块初始化失败时，须逆序清理已成功初始化的模块。

### 6.3 安全性需求

- 目标列表写入前须检查是否超过 `max_targets` 限制，防止缓冲区溢出。
- 滤波窗口边界须做越界保护，不得访问负数或越界索引。
- 所有日志写入前须检查文件句柄非 `NULL`。

### 6.4 可维护性需求

- 各模块须保持独立性，接口通过头文件声明，内部实现细节不对外暴露。
- 关键配置参数须通过 `radar_config.txt` 外部配置文件管理，不得硬编码。
- 构建系统使用 `Makefile`，支持 `make`、`make clean`、`make run` 三种目标。

---

## 7 约束与假设

1. 本系统为单线程仿真实现，不支持多线程并发访问共享数据结构；如需多线程，须在所有全局数据的读写处加互斥锁。
2. 信号采集为软件仿真，非真实硬件接入；实际硬件接入时须替换 `signal_acquire()` 实现。
3. FFT 实现为简化版离散傅里叶变换（O(N²)），仅供仿真使用；生产环境须替换为高效 FFT 库（如 FFTW）。
4. 目标 ID 由时间戳生成，在同一秒内多目标可能产生重复 ID，实际系统须使用唯一 ID 生成策略。
5. 编译环境：GCC，C99 标准，依赖数学库（`-lm`）。
